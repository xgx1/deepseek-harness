# 白名单技能过滤模型

[English](0001-whitelist-skill-filter.md) | 中文

技能可见性默认为拒绝。只有当某条允许规则命中时，技能才会出现在模型的 `<available_skills>` 目录里。这与其它主流智能体框架（Claude Code、Cursor、VS Code）默认「全部可见」的做法相反。

## 考虑过的方案

- **黑名单（默认允许，用户拒绝）**：符合行业惯例。但在装有 300+ 技能的情况下，智能体目录从第一天起就是臃肿的，用户必须逐个拒绝无关技能。「先导入当前目录再拒绝」的流程本质上是多绕几步的白名单。
- **白名单（默认拒绝，用户允许）**：强制用户有意识地整理。用户按前缀批量放行（`dotnet-*`、`self-*`），目录保持精简。UX 代价是真实的（首次运行需要配置），但每轮 25KB → 2KB 的节省会在每个会话里累积。
- **分类预设**：按项目类型随附精选允许清单。暂缓：过于武断，用户终究需要按技能逐个控制。

## 后果

- 首次使用的用户在配置允许规则前会看到空目录。界面通过把当前目录预先导入为允许来缓解，再让用户按前缀批量拒绝。
- DSH 更新带来的新技能会自动匹配已有的允许通配。不匹配任何允许规则的技能在用户操作前不可见——这是设计意图，不是缺陷。
- `disable-model-invocation` frontmatter 被并入本系统（见 ADR-0002）。
